# smm-monitor

Сервис на Python: по ссылке на Telegram-канал и Instagram-аккаунт агентства собирает
метрики **по каждому посту отдельно** (просмотры, лайки, комментарии), вытаскивает
описание поста, определяет регион по описанию и выгружает Excel с двумя рабочими листами.

## Что получается в Excel

| Лист | Что внутри |
|---|---|
| **Ссылки** | строка на каждый пост: `№ · Платформа · Ссылка · Дата · Регион · Описание · Просмотры · Комментарии`. Колонка «Регион» — выпадающий список из справочника. |
| **Регионы** | таблица регионов. Напротив каждого (например, «Туркестанская») живыми формулами считается `Ссылок`, `Instagram`, `Telegram`, `Просмотры`, `Комментарии` + строки «Без региона» и «Всего ссылок». |
| **Справочник** | список регионов и ключевые слова, по которым регион определяется автоматически. |

Формулы покрывают диапазон до 1000 строк листа «Ссылки», поэтому **вставленные руками
ссылки пересчитываются сами** — файл пересобирать не надо. Логика счётчика:

```
=COUNTIF('Ссылки'!$E$2:$E$1001, "*"&$A2&"*")      — сколько ссылок по региону из A2
=SUMIF('Ссылки'!$E$2:$E$1001, "*"&$A2&"*", 'Ссылки'!$G$2:$G$1001)   — просмотры по региону
```

Пост с несколькими регионами в описании попадает в счётчик каждого из них.

## Установка

```bash
cd smm-monitor
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

## Запуск

```bash
# собрать метрики и выгрузить отчёт
.venv/bin/python -m smm_monitor.cli collect \
  --source https://t.me/<канал_агентства> \
  --source https://www.instagram.com/<аккаунт_агентства>/ \
  --limit 100 --out out/smm-report.xlsx

# пустая экселька с листами, формулами и выпадающим списком регионов
.venv/bin/python -m smm_monitor.cli template --out out/smm-template.xlsx

# дозаполнить метрики по ссылкам, вставленным в готовый файл руками
.venv/bin/python -m smm_monitor.cli refill out/smm-report.xlsx
.venv/bin/python -m smm_monitor.cli refill out/smm-report.xlsx --refresh   # и обновить уже заполненные

# пересобрать Excel из уже собранного JSON (сеть не нужна)
.venv/bin/python -m smm_monitor.cli from-json out/posts.json
```

Источники АФМ уже прописаны в `config/sources.json` (`t.me/afm_rk` и
`instagram.com/afm_rk`), поэтому обычный прогон — это:

```bash
.venv/bin/python -m smm_monitor.cli collect --config config/sources.json --limit 100 \
  --json out/afm-posts.json --out out/afm-report.xlsx
```

## Откуда берутся цифры

**Telegram, backend `web` (по умолчанию, без авторизации)** — публичное превью
`t.me/s/<канал>`: ссылка на пост, описание, дата, **просмотры** и сумма реакций (лайки).
Количество комментариев в превью не отдаётся. У канала `@afm_rk` реакции в превью
отсутствуют, поэтому колонка «Лайки» по Telegram пустая — цифры появятся только в режиме `api`.

**Telegram, backend `api`** — Telethon, даёт ещё и комментарии:

```bash
export TELEGRAM_API_ID=... TELEGRAM_API_HASH=...   # my.telegram.org
.venv/bin/python -m smm_monitor.cli collect --source https://t.me/<канал> --telegram-backend api
```

**Instagram** — `instaloader`: лайки и комментарии по каждому посту. Просмотры Instagram
анонимно не отдаёт (у фото их нет в принципе, у reels счётчик виден только залогиненным) —
если нужны просмотры, зайдите под сессией:

```bash
.venv/bin/instaloader --login <ваш_логин>     # один раз, сохранит сессию
export INSTAGRAM_LOGIN=<ваш_логин>
```

Без логина сбор тоже работает, но медленно (Instagram притормаживает анонимные запросы:
100 постов — несколько минут).

## Регионы

Справочник — `config/regions.json`: 20 регионов в том же порядке и с теми же названиями,
что в рабочей таблице (Туркестан, г. Астана, Мангистау, г. Алматы, ВКО, г. Шымкент,
Павлодар, Алмат. обл., Кызылорда, ЗКО, Абай, Костанай, Акмола, Караганда, СКО, Жамбыл,
Актобе, Жетісу, Атырау, Ұлытау). Из него строятся и лист «Регионы», и выпадающий список.

`aliases` — слова для авто-определения региона по описанию поста (регистр не важен):

| Запись | Что совпадает |
|---|---|
| `караганд*` | любое слово с таким началом: «Карагандинской», «Қарағанды» |
| `ско` | только слово целиком — чтобы не ловилось «сколько» |
| `re:(?<!\w)алматы(?!\s*обл)` | регулярное выражение для сложных случаев: «в Алматы», «Алматыда», «Алматы қаласында» — но не «Алматы облысы» |

Авто-определение — это черновик: если в тексте перечислено несколько областей, пост
попадёт в каждую. Регион всегда можно поправить вручную — колонка «Регион» на листе
«Ссылки» снабжена выпадающим списком.

## Приложение для заказчика (без командной строки)

`app.py` — та же логика, но «в один клик». Спрашивает, что сделать:

1. собрать свежий отчёт по каналам из `config/sources.json` — файл ложится на Рабочий стол;
2. дозаполнить файл, в который ссылки вставили руками, — путь к файлу перетаскивается в окно.

Собрать запускаемый файл под текущую систему:

```bash
.venv/bin/pip install pyinstaller
.venv/bin/pyinstaller --noconfirm --onefile --console --name "Отчёт АФМ" \
  --add-data "$(pwd)/config:config" --collect-submodules instaloader --hidden-import bs4 app.py
```

Результат — `dist/Отчёт АФМ` (~12 МБ), Python на машине получателя не нужен.

`.exe` для Windows с macOS не собирается — нужна Windows-машина. Для этого в репозитории
лежит [.github/workflows/smm-monitor-exe.yml](../.github/workflows/smm-monitor-exe.yml):
вкладка Actions на GitHub → «Сборка приложения «Отчёт АФМ»» → Run workflow → готовые
файлы под Windows и macOS скачиваются из artifacts.

## Корпоративная сеть

В сети с проверкой трафика (шлюз подменяет сертификаты сайтов) Python по
умолчанию обрывает соединение: `certificate verify failed`. Поэтому сертификаты
проверяются по хранилищу операционной системы — `truststore` подключается в
[net.py](smm_monitor/net.py) при каждом запуске.

Если корневого сертификата организации нет и в системном хранилище, его можно
положить рядом с программой файлом `сертификат.pem` (или `certificate.pem`) —
приложение само пропишет его в `REQUESTS_CA_BUNDLE`.
